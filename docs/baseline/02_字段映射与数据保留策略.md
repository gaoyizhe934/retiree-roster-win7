## 全列处置

每个非空源标题及无标题但有数据的源列都必须有明确处置：

- PersonField：映射到唯一的可导入目标字段，完成类型／值域校验。
- BatchRawOnly：维护员明确确认仅保存在本地批次原始值，不进入 Person；用 ImportRawCell 保留批次、行列、标题及原值，禁止写公开日志。
- Unsupported：首期不支持，阻断确认，提示处理方式。

默认处置为 Unsupported。两个源列映射到同一目标、重复标题、存在未知列或有值无标题均需人工处理，不能忽略后确认。第 23 列 W 在当前样表为空；未来若有内容也按上述规则处理。

系统分配 PersonId、PersonCode、批次及审计字段，不从源表映射；拼音键由服务初始化并允许维护。无源列的 LifeStatus 走[显式状态确认](01_导入Profile冻结说明.md)。数据类别与级别代码待 Profile 确认，不从“身份”猜测。

FieldSpec 的 source_importable、user_editable、system_managed 分别控制源列导入、人工修改及系统专管字段。PersonId／PersonCode／CreatedAt／UpdatedAt／ImportBatchId／LastModifiedBy 的前两项为 false、最后一项为 true。PinyinSortKey 不可导入，创建时服务初始化，之后允许人工编辑，故不属于永久系统专管字段。LifeStatus 允许明确状态源映射，且需单独确认、解析。

创建请求使用 PersonCreateInput，只有业务输入，没有系统编号、拼音初值或审计字段；服务分配编号、初始化拼音并根据本地操作员与系统时间写审计。编辑请求使用 PersonEditInput／EditableFieldId，不提供系统专管枚举；共享 is_valid_field_change 拒绝强转伪造的字段。完整 PersonRecord 仅作存储／服务输出，不直接作为创建输入。

标签请求使用 TagMutation，包含代码、值、适用年及删除意图；人员关联和 changed_by 是请求上下文，updated_at／updated_by 仅由服务生成，不接收第二套审计值。

## 隐私

NationalId、Phone、RelativePhone、HomeAddress 为敏感字段，默认不打印，UI 默认脱敏。备注及原始批次单元格可能包含个人资料，也禁止直接写公开证据。ExportLogRecord 按原需求在本机私有数据库保存真实 output_path；普通 UI 展示、公共测试证据和 GitHub 日志生成脱敏摘要，不直接披露私有路径。筛选摘要仍脱敏，原始档案与 ImportRawCell 同样在本机保管。
