# 数据字典 v1（D1-A）

状态：**候选 v1，未冻结**。批准人／日期／批准证据：均未提供。本字典由 A 轨编制，字段结构以 Draft 契约 [schema_types.hpp](../../include/retiree_roster/schema_types.hpp)（ContractVersion 4）为当前基线；契约本身未冻结，因此下文的 KNOWN 只表示“在当前基线内一致”，不表示已获批准。

依据顺序见[基线与权威来源](00_基线与权威来源.md)。源列盘点与逐列处置见[源表字段映射](07_源表字段映射.md)，未决口径见[D1-A 未决项清单](09_D1A未决项清单.md)。

## 信息等级

| 等级 | 含义 |
| --- | --- |
| KNOWN | 有需求、规划、原始资料或已提交契约直接支持，且不依赖未确认业务口径 |
| INFERRED | 由表头语义或契约结构合理推断，但没有单独批准 |
| UNKNOWN | 无依据，且现有材料无法推断；包括因无数据行而不可测量的量 |
| REQUIRES_CONFIRMATION | 必须由 R 或甲方给出业务口径后才能定稿 |

**盘点范围（L0 证据）**：公开样表 `reference/员工信息表11111.xlsx`（SHA-256 `427727f5…2cf5b6`）只有一个工作表 `Sheet1`，只有第 1 行（52 个非空标题）与第 3 行（23 个非空标题）有内容，**没有任何数据行**。因此下表所有“值域”“空值可能”“重复风险”均为结构候选，**重复率、空值率、脏数据比例一律 UNKNOWN，不得填写数字**。逐列证据见 [01-source-header-inventory.txt](../evidence/D1-A/01-source-header-inventory.txt)。

命名约定：下文 **P1／P2 指 Source Profile**，**区域 1／区域 2 仅作物理位置描述**。两个 Profile 都是首期支持范围、互不覆盖、分别匹配、分别预检、各自拥有 mapping／profile version（版本化细节属 D3）；canonical Person 由两者共享，**Source Profile ≠ Domain Model**。两份 Profile 的地位确认不等于映射、值域与导入策略已批准：P1 的 5 个 `Unsupported` 列与 8 个机器不可核验的映射语义、以及 P2 的全部值域口径，仍按[未决项清单](09_D1A未决项清单.md)留 D3。

历史问题 A-D1-01（是否还有第二份独立业务工作簿）与 A-D1-07（两套表头体系的性质）已由上述 Owner Decision 关闭；项目管理台账 `reference/七阶段开发任务清单.xlsx` 不是业务数据源。

### 生命周期与不物理删除

| 规则 | 内容 | 依据 |
| --- | --- | --- |
| 不物理删除 | Person 记录只新增与更新；导入、维护、恢复流程都不提供 `DELETE FROM person` 路径 | 需求表 6；台账 D1-A 审查责任 |
| 去世是状态变更 | 去世写入 `life_status` 与 `death_date`，其余历史字段与标签全部保留 | 需求表 6；ADR-0004 |
| 标识符不复用 | `person_id` 与 `person_code` 在记录标记为去世后仍不复用、不重新分配 | R05；[编号口径](03_标识符与编号口径.md) |
| 标签不随状态删除 | 人员标签不因状态变更被删除；慰问按年绑定，不跨年继承 | ADR-0004 |
| 误录纠正 | **口径未定**：契约中 Person 只有 `LifeStatus` 三态，没有“作废／撤销”概念，批次记录也不可删除；错误导入的纠正路径见 A-D1-17 | 待确认 |

首期不得把“去世”当作删除手段，也不得用 `Unknown` 状态掩盖误录数据；不物理删除不等于允许把错误记录永久混入名册（A-D1-17）。

| 字段键 | 载体 | 来源 | 等级 | 说明 |

| tag_code | TagCode | 人工维护 | REQUIRES_CONFIRMATION | 代码表未定；需求级标签为困难、长期患病、慰问 |
| tag_value | Text | 人工维护 | REQUIRES_CONFIRMATION | 值编码待 A/R 确认（ADR-0004 Proposed） |

源表中与标签语义接近、但**尚未确认**可转为标签的列（P1／行 1）：`退休纪念品领取`、`特困年度`、`特困原因`、`国务院特贴`、`抗美援朝`、`退役军人`、`离休、退职`、`厅级`。其中 `特困年度` 可对应 `applicable_year`、`特困原因` 可对应 `tag_value`，其余为标记列。需求与 ADR-0004 只把“困难、长期患病、慰问”定义为人工标签；把上述列升级为标签属于业务口径变更，必须先确认（A-D1-08）。首期不得自动推断困难、疾病或慰问。P1 的 Profile 地位已由 Q2-A 确认，但这**不代表**这些列的语义已冻结。

唯一键建议 `(person_id, tag_code, applicable_year)`；D2 落库前必须明确唯一约束与迁移方式。
