# 重复候选规则草案（D1-A）

状态：**草案，未冻结**。批准人／日期／批准证据：均未提供。本草案只定义“重复候选”的识别与人工处置边界，不定义自动合并、不定义去重后的字段优先级。

依据：[导入 Profile 冻结说明](01_导入Profile冻结说明.md)（未解决重复候选阻断确认、初期禁止自动合并）、[标识符与编号口径](03_标识符与编号口径.md)（工号不能单独作为去重主键）、需求 R05 与 `person_id` 不复用。

## 术语与不可越过的边界

- **重复候选**：两条记录在某些规范化信号上相同，**可能**指向同一个人。它是提示，不是结论。
- 候选识别只允许产生候选与置信档位；**任何候选都必须由维护员显式处置**，系统不得自动合并、自动覆盖、静默丢弃或按工号直接 UPDATE。
- 首期**不做**模糊匹配：不做编辑距离、拼音相似度、同音字、繁简转换或统计模型。规则是确定性的、可复算的、可解释的。
- 候选证据包含敏感字段，只能保存在本机批次与私有数据库；禁止写入公开证据、GitHub 日志或导出摘要。

## 两个作用域

| 作用域 | 定义 | 发现时机 | 依赖 |
| --- | --- | --- | --- |
| 批内重复 | 同一次导入的源文件内，两行或多行互相构成候选 | 预检阶段，仅读源文件 | 无（不需要数据库） |
| 批间重复 | 源行与数据库中既有 Person 构成候选 | 预检阶段，需要查询正式库 | 正式库与 `person_id` 分配 |

两个作用域都必须检测：每个候选（无论批内还是批间）都计入 `duplicate_candidate_count`；尚未处置的候选另计入 `unresolved_duplicate_count`，非 0 时阻断确认。批内候选不因“同一文件”而降级；批间候选不得覆盖既有档案。

## 规范化规则（确定性，可复算）

| 字段 | 规范化 | 说明 |
| --- | --- | --- |
| 姓名 | 删除全部空白（含半角、全角空格与换行），保留其余字符 | 样表中“姓 名”与“姓名”规范化后同键；不做繁简、同音字转换 |
| 身份证号 | 删除空白，字母统一大写 | 15 位与 18 位是否互判为同键**未定**（A-D1-11） |
| 工号 | 删除空白，保留前导零与字母大小写 | 文本比较，不转数字 |
| 电话 | 删除空白与常见分隔符（`-`、`—`） | 是否去除区号与国际前缀未定 |
| 日期 | 按 `DateValue` 精度比较：精度不同即不相等 | 不把 `1955-03` 与 `1955-03-01` 当作同一证据，也不补全缺失组件 |
| 空值 | 规范化后为空的值不参与任何信号 | 空身份证、空工号不得两两互判为重复 |

## 信号与置信档

| 信号 | 条件 | 置信 | 备注 |
| --- | --- | --- | --- |
| S1 | 身份证号规范化后非空且完全一致 | 高 | 最强业务信号，但字段敏感且可能非法 |
| S2 | 姓名一致 **且** 出生日期（FullDate）一致 | 中 | 需要完整日期 |
| S3 | 姓名一致 **且** 出生年月（YearMonth）一致 | 中 | 精度不足时使用 |
| S4 | 工号规范化后非空且一致 | 弱 | 工号可空可重复，单独不足以确认 |
| S5 | 姓名一致 **且** 电话规范化后一致 | 弱 | 电话可能共用；仅在本地比较 |

每个信号独立产生候选，候选携带置信档与命中的信号编号。**所有档位都阻断确认**，直到维护员处置；档位只影响提示顺序与默认建议，不影响是否阻断。信号集合与置信档划分本身是候选口径，待 R 确认（A-D1-18）。

## 人工处置选项

每个候选必须落到下列之一，处置结果与处置人进入批次记录：

| 处置 | 含义 | 首期行为 |
| --- | --- | --- |
| SkipRow | 跳过该源行 | 该行不导入，计入异常报告 |
| ImportAsNew | 作为新人员导入 | 分配新 `person_id`；必须记录理由 |
| LinkExisting | 关联既有 `person_id` | 只建立关联标记；**不合并、不覆盖字段**，字段变更走人员维护服务 |
| DeferManualReview | 标记待查 | 该行不导入，登记到批次未决项 |

禁止项：自动选择处置、按工号覆盖既有档案、把候选直接当重复删除、把未处置候选当作已通过。

## 与预检、revision 和事务的关系

- 处置属于预检语义的一部分；处置变化使 `preview_revision` 失效，必须重新预检。
- 存在未处置候选时不得生成可确认对象；确认接口不接收重复处置参数。
- 入库在单一事务内完成；失败导入不得留下半条记录，`imported_record_count` 必须为 0。

## D3 必测用例（首期验收）

| 编号 | 用例 | 期望 |
| --- | --- | --- |
| DUP-01 | 批内两行姓名相同、出生日期不同 | 不构成候选（或仅弱档提示，口径待确认） |
| DUP-02 | 批内两行姓名与完整出生日期相同 | 构成候选，阻断确认 |
| DUP-03 | 批内两行身份证号一致 | 高置信候选，阻断确认 |
| DUP-04 | 批间身份证号与既有 Person 一致 | 批间候选，禁止自动覆盖 |
| DUP-05 | 工号相同但身份证号不同 | 弱候选；不得自动覆盖既有档案 |
| DUP-06 | 身份证号缺失或非法，姓名与出生年月一致 | 走 S3，仍阻断确认 |
| DUP-07 | 姓名仅空白差异（“姓 名”与“姓名”） | 规范化后同键，构成候选 |
| DUP-08 | 身份证号字母大小写差异（末位 x／X） | 规范化后同键 |
| DUP-09 | 空身份证号的两行 | 不构成候选 |
| DUP-10 | 未处置候选直接确认导入 | 拒绝，返回 `DuplicateCandidate` 类错误 |
| DUP-11 | 处置后修改映射或源文件 | 旧 revision 失效，必须重新预检 |
| DUP-12 | 15 位与 18 位身份证号指向同一人 | 口径未定，见 A-D1-11；首期必须按“不互判”或“人工判定”之一实现，不得默认猜测 |
