# ADR-0003 名单快照与输出一致性

状态：Proposed；批准人／日期／证据：未提供。依据：需求 R04/R05、ExportLog 约束及开发规划 D4 同一筛选结果要求。

提案：GenerateRosterRequest 由同一服务解释 FilterSpec，生成 RosterResult，含 snapshot_id、data_version、generated_at、已展开的筛选条件和已排序 rows。行中保存人员及标签副本、派生年龄／党龄、当次序号。ContractVersion 4 移除可写 total_count 字段，改为 total_count() const 从 rows.size() 即时派生；人数只有一个来源，调用方不能单独设置。此修订仍为 Draft，不改变本 ADR 的 Proposed 状态。

名单快照发布后不可原地修改。服务保管不可变副本，PrintModel 仅持有 const 视图；禁止保留可写别名给 UI。导出、预览、打印请求都仅引用 snapshot_id 和模板的值副本，不接收 FilterSpec 重新筛选。更换模板不能改变名单或序号；模板版本固定在一次输出中。

任意人员、标签、拼音排序键、导入、恢复或迁移改动后，数据版本失效（恢复也不可复用旧版本号）。旧快照的预览、导出和打印一律返回 StaleSnapshot，要求重新生成。输出开始前在服务的同一临界区检查版本并固定快照；操作过程中不混入新数据，不从数据库补列或标签。

同一快照显示 37 人，则 xlsx／预览／打印为同样 37 人、同样顺序。ExportLogRecord 保存快照、模板版本、脱敏条件摘要、人数、真实输出路径、时间、归属和结果。output_path 保存在本机私有数据库，UI 普通展示及公开证据另行脱敏，不能因公开隐私要求丢失本地业务路径。

本轮仅修改契约，未实现快照仓储、版本失效、输出锁或 GDI/xlsx。D4/D5 必须用变更前后对账和旧快照拒绝输出集成测试证明以上行为。
